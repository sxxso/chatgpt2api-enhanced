# ChatGPT2API Enhanced 小白使用指南

按 Windows 本机使用编写。最终你会得到一个浏览器画图工作台，也能把兼容 API 接给自己的客户端。软件不提供 ChatGPT 账号或免费额度。

## 1. 准备

- Windows 10/11；放在普通文件夹，如 `D:\Apps\chatgpt2api-enhanced`，不要直接在压缩包里运行。
- 能访问依赖下载站和 ChatGPT 的网络。
- 自己有权使用、且能正常使用相应功能的 ChatGPT 账号。
- 安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，用于下载 Python 和安装依赖。

如果电脑已有 `winget`，可在 PowerShell 用官方安装方式：

```powershell
winget install --id=astral-sh.uv -e
```

也可按官方页面安装。装好后关闭旧终端再重新打开。无需提前安装 Python：脚本会让 uv 下载 Python 3.13。

## 2. 下载正确的包

打开 [Releases](https://github.com/sxxso/chatgpt2api-enhanced/releases/latest)，下载名称带 **Windows.zip** 的附件。它包含源码、启动入口和构建好的面板。

GitHub 自动附带的 `Source code (zip)` 不带面板，安装时还需要 Node.js。右键 ZIP →「全部解压」，应能看到 `首次安装.cmd`、`启动.cmd`、`停止.cmd` 和 `web_dist` 文件夹。

## 3. 第一次安装

双击 `首次安装.cmd`。它会下载 Python 3.13、安装锁定依赖，并生成自己的 `config.json` 和随机管理员密钥。再次执行会保留已有配置。

Windows 成品包使用内附面板，不需要 Node.js、Bun 或 Docker。下载完成出现 `Ready` 才算安装完成；失败时看最后几行报错，不要只看窗口是否弹出。

如果下载的是源码包或 Git 克隆，先从 [Node.js 官网](https://nodejs.org/en/download) 安装 Node.js。本版使用 Node.js 22 验证；源码安装入口会自动执行 `npm ci` 和 `npm run build`。

## 4. 启动和登录

双击 `启动.cmd`。未自动打开时，在浏览器地址栏输入 `http://127.0.0.1:3000`。

登录框需要的是**本项目管理员密钥**，不是 ChatGPT 密码，也不是 OpenAI API Key：

1. 找到项目目录里的 `config.json`，用记事本打开。
2. 找到 `"auth-key": "一串随机字符"`。
3. 只复制双引号里面的字符，粘贴登录。

不要公开这份文件。以后继续用同一密钥；自己改密钥后，重启服务并重新登录。

## 5. 导入自己的账号

进入「号池管理 → 导入」，选择对应来源。第一次优先用自己已登录的网页账号：

1. 在浏览器登录自己的 ChatGPT。
2. 用同一浏览器打开 `https://chatgpt.com/api/auth/session`。
3. 在本项目导入弹窗选择 Session JSON 入口，粘贴该页面的 JSON；也可选 Access Token，填写其中的 `accessToken`。
4. 导入后刷新号池，确认账号状态和额度。不要把 Session JSON 发给别人。

弹窗也支持相应的 Codex/CPA JSON 和 OAuth 入口。不同来源权限可能不同；格式与保存成功不代表所有模型都可调用。

## 6. 模型列表为什么为空

本分支只展示近期实际验证通过的模型。新安装不附带维护者的验证记录，所以导入账号后列表仍可能为空。

最简单的方法：

1. 保持服务运行，导入至少一个可用账号。
2. 双击 `验证默认生图模型.cmd`。
3. 读完提示，输入 `YES`。它会发起一次真实生图，可能消耗自己的图片额度。
4. 等待结果；报错、拒绝、型号不匹配都不会当作可用模型。
5. 验证通过后，在「号池管理 → 模型实测结果」点击「刷新结果」，再刷新画图页。

默认验证 `gpt-image-2.6-sunburst`。如果上游拒绝，可在项目目录的 PowerShell 手动验证另一个支持的标识，例如：

```powershell
.\.venv\Scripts\python.exe scripts/probe_pool_models.py web-image --model gpt-image-2 --timeout 180
```

这也会产生一次真实请求。不要连续批量重试。成功后在「设置 → 基础配置 → 默认生图模型」选择已验证型号。

「刷新结果」只读取记录，不会自动测试。记录默认 7 天有效，过期需重新验证。型号是项目发送与上游返回的标识，不能独立证明上游模型权重。

## 7. 第一张图片

打开「画图」，先用 1 张图片和简单提示词测试：

> 白色背景，一只坐着的橘猫，简洁插画，不要文字。

选已验证模型，点击生成。成功后打开预览或下载原图。参考图编辑则先上传图片，再说明要改的部分。

- **排队**：查看位置，等前面的任务完成；「取消排队」只取消未开始的任务。
- **可继续等待**：查询原会话，不会另起生成。
- **没有续等按钮**：恢复信息不足，先看报错，再决定是否重新生成。
- **刷新页面**：图片会话保存在当前浏览器；换浏览器或设备不会自动同步。

尺寸是请求参数，上游可能不按指定像素返回。2K/4K 以下载文件的实际尺寸为准。SVG/GIF/复杂度控件不在本版已接通范围。

## 8. 代理

进入「设置 → 基础配置 → 全局代理」，填代理软件实际提供的 HTTP 地址，例如 `http://127.0.0.1:你的端口`，保存后测试。

端口要去自己的代理软件里查，不能照抄别人的端口。账号专用代理、稳定代理运行时和环境变量也可能影响线路；全局代理为空不一定代表直连。修改环境变量后通常需要重启服务。

Docker 内的 `127.0.0.1` 指容器自身。Windows Docker Desktop 连接宿主机代理时通常用 `host.docker.internal` 和实际端口。建议先跑通本机方式。

## 9. 给别人使用

开源是让别人下载后自己运行，不会公开你的本机账号池。`127.0.0.1` 只能本机访问。

如果另外部署了可访问的服务，在「设置 → 用户密钥」为每个人创建普通用户密钥：

| 设置 | 含义 |
| --- | --- |
| 每日图片额度 | 成功图片数；0 不限，按北京时间自然日统计 |
| 用户并发 | 新用户默认 1；0 跟随全局，仍受总上限约束 |
| 允许型号 | 留空允许全部支持型号，可限制或禁止生图 |
| 到期时间 | 留空长期有效，到期不能认证 |

先设置限额，再分享普通用户密钥。管理员不受普通用户图片限额限制，因此不要共享管理员密钥。文本接口不由“每日图片额度”限制。

历史分区只是浏览器本地隔离，不是完整多租户文件权限。公网部署需另配 HTTPS、访问控制和图片数据保护。本指南不会自动放行防火墙或创建隧道。

## 10. 接入其他客户端

- Base URL：`http://127.0.0.1:3000/v1`
- API Key：本项目普通用户密钥，或仅供自己使用的管理员密钥。
- 模型：`GET /v1/models` 当前返回的型号。

图片生成/编辑省略模型时用默认生图型号；显式指定的型号优先。客户端能否显示图片按钮取决于它自己的功能，有些只支持聊天。

## 11. 停止、更新与备份

- **停止**：双击 `停止.cmd`。关浏览器不会停止后台服务。
- **备份**：等任务结束，停止服务，复制自己的 `config.json` 和整个 `data` 到私密位置。
- **Windows 包升级**：停旧服务，解压新包到新文件夹，复制旧 `config.json` 和 `data` 过去，再首次安装、启动。
- **源码升级**：备份并停止后 `git pull`，再执行下面的重建命令，需要 Node.js。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-windows.ps1 -RebuildWeb
```

浏览器本地会话历史不随服务器 `data` 自动同步。JSON 的 `.bak` 是上一份有效文件；遇到损坏先停机、另存原文件再检查备份，别把账号文件改成 `[]`。队列和限额按单进程运行，不要启动多个 workers 写同一数据目录。

## 12. 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 uv | 安装后重开终端，再执行首次安装 |
| 找不到 Node.js | 源码包需要 Node；想少装软件则下载 Windows 附件 |
| 连不上 3000 | 运行启动入口，查看 `data/local-server.stderr.log` |
| 端口被占用 | 停止旧实例或占用端口的其他应用，别反复开窗口 |
| 密钥无效 | 复制本项目 `auth-key` 的值，不带引号和空格 |
| 健康 degraded | 空池或无可用账号时可能出现；先看 `/version`，再查账号 |
| 模型列表为空 | 按第 6 节真实验证；刷新结果不会代替验证 |
| 403 | 区分用户型号权限和上游账号拒绝，查看具体错误 |
| 429 | 检查用户日额度、独立并发、总队列和账号额度 |
| 生成超时 | 有按钮就续等原任务，先看报错再决定是否新建 |
| 页面还是旧的 | `Ctrl+F5`，确认 `web_dist` 已更新；源码版需重建 |

请求帮助时附版本、最后几行报错和步骤即可，去除令牌、Cookie、邮箱、代理密码与私密链接。
