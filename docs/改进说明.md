# 改进说明与验证边界

本分支从上游 `92dd80e` 的源码及本地改进快照整理而来，未继承维护者的私密配置、账号、图片、模型记录和本地 Git 历史。原始 LICENSE 保留。

## 可靠性

生图失败只记录一次结果，归还自己持有的并发槽位。保存原账号引用、上游会话和阶段以支持超时后继续查询。刷新和重启后仍保留可恢复上下文；缺失上下文的旧任务不会显示无效续等按钮。JSON 通过临时文件原子替换，保留上一份有效 `.bak`，损坏时拒绝覆盖，保存失败时回滚内存修改。

## 目录和资源控制

公开目录、API 和画图选择器使用同一批近期实测结果。异常回退、失败、过期和路由不符的条目不展示；网页与原生图片探测分开判断。目录为空时需要自己完成首次验证，不分发他人的成功记录。

全局图片并发默认 4，后台排队容量默认 32，等待超时默认 600 秒。直接图片请求和后台任务共享执行上限，等待队列各自有容量；多张生成与续等同样受限。重启不会自动重放尚未开始的任务。

## 用户限制

普通用户可配置每日图片数、独立并发、允许型号和到期时间。已完成结果使用持久编号去重；失败不算成功额度，跨零点按获得执行位置时的日期归属。认证后的身份覆盖外部请求中伪造的内部字段。

修复了保存失败仍生效、失败后立即续等竞态、单用户积压突破排队容量、多图错误码变为 502、续等空下载误记成功等问题。本地图片历史按用户分区，并将异步写入绑定到最初的用户。

## Windows 与发布

增加首次安装、随机密钥、锁定依赖、预构建面板包、模型验证入口和小白指南。模型探测失败或型号不匹配返回非零状态，避免把“脚本运行完了”当作可用。

## 验收范围

- `scripts/check_reliability.py` 为指定离线回归集合，使用假账号、临时目录和本地图片。
- 首版公开准备时，155 项指定回归、前端构建及 TypeScript 检查通过；必需入口和 Windows 包面板文件纳入发布检查。
- 前端生产构建强制检查 TypeScript。
- Windows 包按无真实账号环境验证安装、启动、登录、页面和模型空目录行为；不随发布自动消耗真实图片额度。
- 模型连通性、上游权重版本、精确输出分辨率不能用离线测试或 HTTP 200 代替确认。
- 当前协调机制仅用于单进程；跨实例限额、跨文件断电事务、完整多租户文件权限未完成。
- 账号刷新策略、连续失败冷却、代理实际来源展示、实际图片尺寸及新增图片格式留待后续独立改进。
